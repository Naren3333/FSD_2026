# Learning Ledger interaction contract

Business authority: docs/requirements.md sections 6, 8, 15–18 and docs/decisions/0001-foundation.md. Teachers own their classrooms. Students submit once; grades are immutable after teacher finalization. All authorization remains server-enforced.

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| Form | shared field component + Reactive Forms | this contract | create, submit, review | Angular tests + browser E2E |
| Select/Listbox | native select | DESIGN.md | classroom, topic, type (students answer multiple choice with a radio group) | keyboard/browser |
| Date | native datetime-local input | DESIGN.md; assessment opening/due-date APIs | assessment scheduling | component + browser E2E |
| Scrollbar | global styles.css | DESIGN.md | document and horizontal tables | static + browser |
| Toast | shared status component | this contract | status, error | unit + browser |
| CRUD | feature components + Api service | API/domain contracts | create, refresh list, edit/publish/delete draft, edit/delete published assessment, mark, release, remove enrollment, delete classroom, delete material, archive curriculum, create/edit/delete bank question, create resit, delete own account | live E2E |

Creation retains the owning view, refreshes the real list, clears only successfully saved input, and announces completion. Validation keeps entered values and focuses the first invalid control. Mutations disable their submit button. Failed operations retain input, explain the failure, and allow explicit retry; no automatic mutation retries. Authentication failures offer sign-in without deleting drafts. Tokens remain in memory through Keycloak JS; on load the app asks Keycloak, without showing its login page, whether the browser is still signed in, so a refresh keeps the user signed in. While a signed-in user's profile loads, the workspace shows a loading state, never the signed-out welcome; if it fails to load, it explains why and offers Try again and Sign out.

Classroom and refresh. The classroom choice is remembered per user in this browser and restored on sign-in; a saved classroom that is gone, or blocked storage, falls back to the first classroom. Assessments, the question bank, the dashboard, Home, Materials, My results, progress, Grading review and Students re-read in place when shown again (at most every 20 seconds), keeping what is on screen; a section that failed keeps its Try again. Each page header's icon Refresh button stays as the explicit way to re-read. Progress loads by itself, with no View button; a teacher's student select loads at once, and its empty option clears the evidence with the text "Choose a student to see their finalized evidence."

Each section stays mounted after the user leaves it, and the views inside Assessments (list, editor, preview, resit builder), the question bank and Grading review are chosen by the address, so a half-written form or a loaded list is still there on return; page unload warns when a form is dirty. Classroom context changes are disabled while work is unsaved. An unsent chat question is the exception: it is kept with its classroom and comes back when that classroom is chosen again, so it does not lock the classroom; it still warns on unload and refuses sign-out. An answer still streaming does lock it. The sidebar's Current classroom select and the Classrooms page's Open buttons are disabled with the note "Finish or clear your current form before changing classrooms.", and Sign out is refused with "Finish or clear your unsaved forms before signing out." Finalization uses an explicit review reason and an app-owned confirmation dialog; cancel is the initially focused action. Removing a student from a classroom uses the same app-owned confirmation dialog with Cancel focused; it keeps their submissions and grades and is undone by enrolling them again. Deleting a classroom uses the same dialog with Cancel focused; it ends everyone's access, unenrolls its students (their accounts are kept) and purges the classroom's materials, assessments, submissions, grades, performance evidence and chat threads in every service. It cannot be undone. Deleting an assessment uses the same dialog with Cancel focused: a draft, or a published one no student has submitted (its students' saved work goes with it). Once a student has submitted, its editor offers only the title, due date and late policy, and Delete opens the same dialog titled "Delete this assessment and its grades?": it counts the submissions, says every grade for them goes too (finalized and released ones included) and confirms with "Delete assessment and grades". It cannot be undone. A teacher's Preview assessment button opens the preview on its own page; its Close preview button returns to the list and focuses that Preview assessment button. Releasing an assessment's results uses the same dialog and cannot be undone. Deleting a teaching material (or a rubric or marking scheme uploaded before ADR 0009) uses the same dialog with Cancel focused: it deletes the document and its original for good, and the assistant and AI drafting stop using it, while questions keep the passages they copied. It cannot be undone; afterwards focus moves to the Classroom library heading and the deletion is announced. When the list cannot be re-read after a delete, the deletion is still announced and the page's status says the list could not be refreshed. Archiving a curriculum topic uses the same dialog with Cancel focused; it moves the topic to the teacher's Archived topics list, out of every picker for new questions, and deletes nothing (existing assessments and evidence keep it and still show its name). In the editor, a question that still has an archived topic shows it as "(archived)", which cannot be chosen again, and asks for an active topic before the assessment saves. Restore there makes it active again, without a dialog since it is undone by archiving. Deleting one's own account, from the Profile page (in the sidebar's account block), uses the same dialog with Cancel focused, titled "Delete your account?" and confirmed with "Delete my account": it says what goes (a student's submissions, grades, evidence and chat threads; a teacher's chat threads) and that it cannot be undone, then signs the user out. A teacher who still has classrooms sees how many and must delete them first, with the button disabled and described by that message; unsaved work elsewhere blocks it with a message. A failure keeps the dialog open with the reason. Deleting a bank question uses the same dialog with Cancel focused, titled "Delete this bank question?" and confirmed with "Delete question": it says assessments that already use a copy keep theirs, and cannot be undone; afterwards focus moves to the Your questions heading, the deletion is announced and the list is re-read. No other delete UI in this milestone.

Assessments are drafts until published; the editor keeps unsaved work and warns on unload, and students never see drafts. Students' answers are saved as they type (the result is announced politely, a failure keeps the answers), past-due and closed states are explained in words, and written answers show a character count. When the teacher changed the assessment after the student opened it, submitting says "This assessment changed since you opened it. Open it again to see the current questions" and offers Open it again, which keeps their answers to the questions that are still there. In Grading review, questions waiting for the teacher are counted on each grade; marking happens in the grade panel with rubric levels as radio groups, points and optional feedback; finalizing with a question unmarked keeps the input and focuses the first missing mark. AI suggestions are labelled as AI-written, show the student's quoted words, and change nothing until the teacher chooses "Use suggestion" and then saves or finalizes. In the editor, short-answer and written-response questions take up to five marking points (ADR 0009): the teacher writes one and adds it, or removes one; the empty state invites a first point, and a full question says to remove one first. A suggestion says how many marking points it read and shows them; students never see marking points. Uploads are teaching material only; there is no marking-scheme search. Teachers can also have AI draft questions from chosen teaching materials ("Generate questions"), and draft accepted answers or a rubric and marking points for a question they wrote from the teaching materials ("Draft marking guidance"). Each explains its loading, no-document and failure states in place, labels its output as AI-written with the passages it came from, and changes nothing until the teacher adds a draft or chooses "Use this"; guidance for a question that was reworded since is not used. Keeping or discarding a draft moves focus to the next draft, or back to Generate. The per-question and per-assessment marking-point limits hold for both; marking points that do not fit are left out and said so. Marking points read "Written by AI" or "Written by you" while the editor is open (after a reload both read "Written for this question"; one copied from a marking scheme before ADR 0009 names its document); generating and drafting spend the teacher's daily AI allowance. On Learning performance, once a teacher has opened a student's evidence, "Interpret results" asks an agent for a draft interpretation (ADR 0014): it shows its loading and failure states in place, is labelled "AI draft for your review", shows every statement with the questions it rests on (assessment, prompt and marks), says how many statements were left out by the checks, lists the agent's steps under "How the agent worked", and changes no grade. Opening another student clears it. Students never see it; their page says generated practice is not available yet.

Grading review's address holds the open assessment and grade (`/review?assessment=&grade=`): Back and Forward move between grades, a bare `/review` keeps the open grade, and a classroom change clears both. "Next to mark" opens the next draft in queue order, wrapping and ignoring the status filter; it reads "Continues on the next page" when it pages on, and is disabled with "Nothing left to mark here" when no draft is left. "Previous grade" opens the row before in the queue as shown. After finalizing, the next draft opens with focus on its heading; with none left, focus goes to the queue heading. Close and "← All grades" return focus to the row's button. Under 1100px "← All grades" refuses while marks are unsaved, and Close discards them; every refusal scrolls the grade's status into view. The status filter chips (All, To mark, Drafts, Finalized) work on the loaded page only and reset on a new page, assessment or classroom. A finalized grade opens as a read-only "View grade" panel, and correct auto-marked answers collapse behind "Override".

Students and Classrooms. The Students page (teachers, under Teach) holds the classroom's roster beside the school's list. Its subtitle reads "<N> enrolled in <classroom>", or "Choose a classroom to see its students." with no classroom, and its roster empty text says to enroll them from All students. Classrooms is a create form above a grid of cards: the current classroom's card carries a "Current" chip and a Students link, and "Open <name>" picks that classroom and goes to `/dashboard`. Delete is an icon button named "Delete <name>", and its confirm dialog is unchanged.

Materials. The drop zone is an extra for mouse users; the file picker is the keyboard way in. Each document's status chip always has its text: Indexed (good), Indexing failed (danger), Not indexed (warning), Indexing (with a clock icon) and Text extracted (plain). Delete is an icon button named "Delete <title>".

Question bank. The Question bank page (teachers, under Teach after Assessments, ADR 0017) lists the teacher's own questions twenty at a time, newest change first, filtered by prompt search, topic and type ("Search bank"; "Clear filters" when any is set). Each row shows the prompt, type, marks and topic; a question whose topic is archived shows "(archived)" and says it cannot be added to an assessment. The empty text says to choose Save to bank on a question of a saved assessment, or New question; with filters set it says nothing matches. New question and Edit open the question's form at `?edit=new` or `?edit=<id>`: type, prompt, topic, marks and the type's answer fields or rubric, with no marking points or passages. Saving ("Add to bank" or "Save question") returns to the list, re-reads it from page one and announces the result; a full bank (2,000), an invalid or archived topic and a question deleted elsewhere are explained in place with the input kept. Leaving the form with unsaved changes keeps it, and the list offers Continue editing; opening another question first is refused with "Save or discard the question you are editing first." The form does not lock the classroom, since the bank is the teacher's own.

Resits. "Create resit" on a published row of the teacher's assessment list, and on the chosen assessment in Grading review, opens the resit builder at `/assessments?resit=<id>` (ADR 0017); Back and Forward work as for the editor, and a classroom change returns to the list. It makes no AI call. The assessment, its finalized grades, the roster and the bank each load on their own, with their loading text, their error and a Try again button; the header's "Refresh resit choices" re-reads them all and keeps the choices. A draft or another classroom's assessment is explained in place. Students: every student on the roster, by name, with "Lost marks" and their finalized marks; those who lost marks on a finalized grade start ticked (drafts suggest nothing, since they show no marks yet). Suggestions read at most five pages of 100 grades and say "Suggestions use the first 500 results" when more remain; with none finalized it says so, and any student can still be ticked. 1 to 100 students; at 100 the rest are disabled with why. Questions: the original's, the ones chosen students lost marks on ticked until the teacher changes a question themselves; then the bank, shown for the topics where chosen students lost marks (from the grades' evidence, else the original's questions), with "All topics" in the topic select. With exactly one student chosen each bank question they answered before shows "Already answered", and "Hide already answered" leaves those out. Archived-topic bank questions cannot be ticked. Chosen bank questions stay chosen across topics and pages, listed under "Chosen from your bank" with Remove. 1 to 50 questions in all; at 50 the rest are disabled. Title is optional, and empty takes "<original> (resit)". "Create resit draft" with no student or no question says which and focuses that part. A refusal (a student no longer enrolled or deleted, a bank question gone, an archived topic, the original no longer published or changed) shows in place with what to do, and every choice is kept. On success the new draft opens in the editor (replacing the builder in history), the editor announces "Resit draft created for N students. Review it, then publish it.", and the editor shows "Assigned to N students: only they can see it." The teacher publishes it like any draft; students see a "Resit" chip.

Results, progress and chat. Each question's outcome chip on My results (Correct, Part marks, Incorrect) always carries its word. From 1000px the chat page keeps the question form under the messages and follows a streaming answer while the user is at the end of the conversation; when the user has scrolled up, "Jump to latest" appears and moves focus to the Messages region.

Materials, assessments and the question bank use server pages of twenty with totals and Previous/Next controls. Classrooms and active/archived topics load metadata through bounded server pages for complete pickers, and display twenty at a time. The school's students and the class dashboard's topics table are paged on the server (ten and twenty at a time). A deletion that empties the final page falls back to the last available page. Changing classrooms resets its lists to page one; stale responses cannot overwrite the current view. Empty states explain the next action. Shared feedback appears next to the action that caused it and takes no space while empty. Errors appear inline; status has a polite live region.

Unsupported AI actions are explanatory text with disabled controls. PDF, Markdown, PPTX and DOCX uploads show their indexing status (indexing, indexed with passage counts and page/slide counts only where meaningful, or failed with a reason and a teacher-only retry); plain text files say they are not indexed. The existing file input accepts these formats with server-enforced limits; PowerPoint speaker notes are included, as stated beside the picker. Chat questions stay in the field until the chatbot accepts them, answers stream with a Stop control, every answer ends answered, with no matching material, failed or stopped, and failures appear inline under the question form with the question kept for retry. Answers render the model's Markdown subset (paragraphs, lists, headings, bold, italic, code) as text, never as HTML; each source shows the whole passage the model was given, its page range for PDFs, slide range for PPTX, or section path for Markdown/Word, and a control that opens the original document (at its first cited page for PDF only). Displayed metrics come only from finalized evidence. The teacher's Class dashboard loads each of its parts (grading counts, roster, submissions, class topics) on its own, so one failing service shows its error in place while the rest still load; each part has its loading and empty state, and the topics table scrolls sideways on narrow screens. The student's Home does the same for their to-do list, recent results and topics to practise; its waiting-for-review count is derived from their own submitted assessments and finalized results, never from draft grades. Dates/numbers use en-SG; people, assessments, questions and topics are shown by the names their owning services return; an id is shown, as a plain identifier, only when no name exists.
