# Learning Ledger interaction contract

Business authority: docs/requirements.md sections 6, 8, 15–18 and docs/decisions/0001-foundation.md. Teachers own their classrooms. Students submit once; grades are immutable after teacher finalization. All authorization remains server-enforced.

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| Form | shared field component + Reactive Forms | this contract | create, submit, review | Angular tests + browser E2E |
| Select/Listbox | native select | DESIGN.md | classroom, topic, type | keyboard/browser |
| Scrollbar | global styles.css | DESIGN.md | document and horizontal tables | static + browser |
| Toast | shared status component | this contract | status, error | unit + browser |
| CRUD | feature components + Api service | API/domain contracts | create, refresh list, edit/publish/delete draft, edit/delete published assessment, mark, release, remove enrollment, delete classroom, delete material, archive curriculum, delete own account | live E2E |

Creation retains the owning view, refreshes the real list, clears only successfully saved input, and announces completion. Validation keeps entered values and focuses the first invalid control. Mutations disable their submit button. Failed operations retain input, explain the failure, and allow explicit retry; no automatic mutation retries. Authentication failures offer sign-in without deleting drafts. Tokens remain in memory through Keycloak JS; on load the app asks Keycloak, without showing its login page, whether the browser is still signed in, so a refresh keeps the user signed in. While a signed-in user's profile loads, the workspace shows a loading state, never the signed-out welcome; if it fails to load, it explains why and offers Try again and Sign out.

Tab panels stay mounted to retain work; page unload warns when a form is dirty. Classroom context changes are disabled while work is unsaved. Finalization uses an explicit review reason and an app-owned confirmation dialog; cancel is the initially focused action. Removing a student from a classroom uses the same app-owned confirmation dialog with Cancel focused; it keeps their submissions and grades and is undone by enrolling them again. Deleting a classroom uses the same dialog with Cancel focused; it ends everyone's access, unenrolls its students (their accounts are kept) and purges the classroom's materials, assessments, submissions, grades, performance evidence and chat threads in every service. It cannot be undone. Deleting an assessment uses the same dialog with Cancel focused: a draft, or a published one no student has submitted (its students' saved work goes with it). Once a student has submitted, its editor offers only the title, due date and late policy, and Delete opens the same dialog titled "Delete this assessment and its grades?": it counts the submissions, says every grade for them goes too (finalized and released ones included) and confirms with "Delete assessment and grades". It cannot be undone. A teacher's Preview assessment button toggles to Close preview; the preview's own Close preview button closes it and returns focus to that button. Releasing an assessment's results uses the same dialog and cannot be undone. Deleting a teaching material (or a rubric or marking scheme uploaded before ADR 0009) uses the same dialog with Cancel focused: it deletes the document and its original for good, and the assistant and AI drafting stop using it, while questions keep the passages they copied. It cannot be undone; afterwards focus moves to the Classroom library heading and the deletion is announced. When the list cannot be re-read after a delete, the deletion is still announced and the page's status says the list could not be refreshed. Archiving a curriculum topic uses the same dialog with Cancel focused; it moves the topic to the teacher's Archived topics list, out of every picker for new questions, and deletes nothing (existing assessments and evidence keep it and still show its name). In the editor, a question that still has an archived topic shows it as "(archived)", which cannot be chosen again, and asks for an active topic before the assessment saves. Restore there makes it active again, without a dialog since it is undone by archiving. Deleting one's own account, from the Profile tab, uses the same dialog with Cancel focused, titled "Delete your account?" and confirmed with "Delete my account": it says what goes (a student's submissions, grades, evidence and chat threads; a teacher's chat threads) and that it cannot be undone, then signs the user out. A teacher who still has classrooms sees how many and must delete them first, with the button disabled and described by that message; unsaved work elsewhere blocks it with a message. A failure keeps the dialog open with the reason. No other delete UI in this milestone.

Assessments are drafts until published; the editor keeps unsaved work and warns on unload, and students never see drafts. Students' answers are saved as they type (the result is announced politely, a failure keeps the answers), past-due and closed states are explained in words, and written answers show a character count. When the teacher changed the assessment after the student opened it, submitting says "This assessment changed since you opened it. Open it again to see the current questions" and offers Open it again, which keeps their answers to the questions that are still there. In Grading review, questions waiting for the teacher are counted on each grade; marking happens inline with rubric levels as radio groups, points and optional feedback; finalizing with a question unmarked keeps the input and focuses the first missing mark. AI suggestions are labelled as AI-written, show the student's quoted words, and change nothing until the teacher chooses "Use suggestion" and then saves or finalizes. In the editor, short-answer and written-response questions take up to five marking points (ADR 0009): the teacher writes one and adds it, or removes one; the empty state invites a first point, and a full question says to remove one first. A suggestion says how many marking points it read and shows them; students never see marking points. Uploads are teaching material only; there is no marking-scheme search. Teachers can also have AI draft questions from chosen teaching materials ("Generate questions"), and draft accepted answers or a rubric and marking points for a question they wrote from the teaching materials ("Draft marking guidance"). Each explains its loading, no-document and failure states in place, labels its output as AI-written with the passages it came from, and changes nothing until the teacher adds a draft or chooses "Use this"; guidance for a question that was reworded since is not used. Keeping or discarding a draft moves focus to the next draft, or back to Generate. The per-question and per-assessment marking-point limits hold for both; marking points that do not fit are left out and said so. Marking points read "Written by AI" or "Written by you" while the editor is open (after a reload both read "Written for this question"; one copied from a marking scheme before ADR 0009 names its document); generating and drafting spend the teacher's daily AI allowance.

Lists are capped by APIs at 100 (curriculum 200); the UI states this limit. The school's students and the class dashboard's topics table are paged on the server (ten and twenty at a time) with Previous/Next controls; other lists are not yet paged. No search or selection feature is claimed. Empty states explain the next action. All shared feedback reserves space. Errors appear inline; status has a polite live region.

Unsupported AI actions are explanatory text with disabled controls. PDFs show their indexing status (indexing, indexed with page and passage counts, or failed with a reason and a teacher-only retry); text files say they are not indexed. Chat questions stay in the field until the chatbot accepts them, answers stream with a Stop control, every answer ends answered, with no matching material, failed or stopped, and failures appear inline with the question kept for retry. Answers render the model's Markdown subset (paragraphs, lists, headings, bold, italic, code) as text, never as HTML; each source shows the whole passage the model was given, its page range, and a control that opens the original PDF at its first page. Displayed metrics come only from finalized evidence. The teacher's Class dashboard loads each of its parts (grading counts, roster, submissions, class topics) on its own, so one failing service shows its error in place while the rest still load; each part has its loading and empty state, and the topics table scrolls sideways on narrow screens. The student's Home does the same for their to-do list, recent results and topics to practise; its waiting-for-review count is derived from their own submitted assessments and finalized results, never from draft grades. Dates/numbers use en-SG; people, assessments, questions and topics are shown by the names their owning services return; an id is shown, as a plain identifier, only when no name exists.
