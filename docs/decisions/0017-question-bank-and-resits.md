# ADR 0017: Question bank and resits

Status: accepted 2026-11-01, after five independent reviews the same day. The project owner asked to plan the question bank and resits, which ADR 0004 lists as not built yet and the brief gives to Assessment ("Question banks", "Assignments"). The plan is `plans/question-bank-and-resits.md`. This amends ADR 0004, and ADR 0006, which expected the bank to reuse `sources`.

## Context

A question exists only inside the assessment it was written for. A teacher who wants to use it again copies it by hand, and a kept generated question is lost to every later assessment. Each student can submit an assessment once, so a student who did badly has no second attempt. The only way to give one today is a new assessment for the whole class.

## Decision

### The bank

**Each teacher has one question bank, kept by Assessment.** A bank question is an assessment question without its id, its `sources` or its `marking_scheme`: type, prompt, options, answer key, tolerance, accepted answers, rubric (with any model answer), length limit, points, topic and origin. It belongs to the teacher who saved it, within their organization, and can be used in any of their classrooms, since topics are organization-wide (ADR 0007). It is validated, given defaults and topic-checked with Curriculum exactly as an assessment question is. Only its owner can list, read, change or delete it, and no student can reach it. A bank question on a topic since archived stays in the bank, but adding it to an assessment is refused (422 `INVALID_TOPIC`, as for any question). A teacher can have up to 2,000 bank questions (409 `BANK_FULL`); every bank create holds an exclusive per-teacher bank lock, so two saves cannot both pass the count. Checks that call other services (topics with Curriculum, the roster with Identity) run before any lock is taken, never while one is held. Sharing a bank with other teachers is not part of this decision.

**The bank holds no passages.** Source passages and marking points quote one classroom's documents, so they stay with the assessment they belong to. Saving a question to the bank leaves them out, a bank request that carries them is refused (422), and a question added from the bank has none; AI marking then works from the rubric and model answer, as for any question written without marking points. A resit that copies questions from its original copies their passages too, since it is in the same classroom. So no classroom's material is ever kept outside that classroom's assessments, and deleting a classroom needs nothing from the bank. Assessment does not consume `content.deleted.v1`, so passages already in an assessment, and those a resit copies from it, keep the text of a material deleted since; they are teacher-only, and this known gap is not widened by the bank.

**Bank and assessments hold copies, linked outside the question.** Adding a bank question to an assessment copies it as a new question. Saving an assessment question to the bank copies it the other way. Changing or deleting either side never changes the other, so a published or submitted assessment is never edited behind the teacher's back. Each assessment question can name one bank question it came from, in a link table outside the question, so the question JSON, the "has the marking changed" check and `assessment.submitted.v4` (whose questions allow no extra fields) are unchanged. Links are declared by the teacher's own requests and only checked to name the teacher's own bank questions: they drive nothing but the teacher's own "already answered" hints, so a wrong link harms no one else (an edit from an out-of-date second tab can drop links made since, with the same small effect). A link is a plain reference, not a foreign key, so deleting a bank question writes nothing to assessments; a link to a deleted bank question is ignored wherever links are read. Copying a question into a resit carries its link along, so a resit of a resit still names the bank question it came from. Saving a question whose link names a bank question the teacher still has is refused (409 `ALREADY_IN_BANK`, with that bank question's id), so the teacher updates that bank question or saves a new one; a link to a deleted bank question is replaced by the new save. Saving to the bank works on any assessment the teacher owns, including one with submissions, because it writes only the bank and the link, never the assessment.

### Resits

**A resit is its own assessment for chosen students.** `POST /v1/assessments/{id}/resits` makes a resit of a published assessment the teacher owns, including another resit. It creates a draft in the same classroom with `resit_of` set to that assessment, a list of assigned students (1–100, each on the roster and not deleted; a resit for more students than that is better given as a new assessment for the class) and 1–50 distinct questions, from the original and then the bank, in the order given. A bank id that is not one of the teacher's bank questions is 422 `INVALID_BANK_QUESTION`. It copies the original's late and release policies, its AI marking only when a teacher-marked question remains, and no dates; the title defaults to the original's with "(resit)", cut to the title limit. A question id the original no longer has is 409 `ASSESSMENT_CHANGED`. The teacher edits and publishes it through the normal flow, with its own dates, late policy, release policy and AI marking. `resit_of` is a plain reference, not a foreign key: a resit whose original was deleted keeps working, and its page says the original was deleted. Only the server sets `resit_of`, whether an assessment is assigned, and its assignees; the ordinary create and edit requests cannot.

**Only resits are assigned, and an assigned assessment is never open to everyone.** An assessment is either for the whole class, as every assessment is today, or assigned. Which one is fixed when it is created: resits are assigned, nothing else is. An assigned assessment is visible only to students who are on its list and on the roster. When its list is empty, through a purge or otherwise, nobody sees it.

**Changing who is assigned.** `PUT /v1/assessments/{id}/assignees` replaces a resit's list, before or after submissions. The new list must not be empty (422). A student being added must be on the roster and not deleted; students already on the list stay without that check, so a student who submitted and then left the class never blocks the list. A student who has submitted cannot be removed (409 `HAS_SUBMISSIONS`). Removing a student deletes their saved answers to it. Every requested student is checked against deleted accounts under their account lock before the change, and only the rows that actually change are written, so a student deleted meanwhile is never put back. The change runs under the assessment's row lock, and submitting and autosaving both re-check the list in their own transaction after taking that row's lock, so a removed student can neither submit nor save afterwards.

**Every student path checks the assignment.** A student who is not assigned gets the same answer as for an assessment that has not opened: left out of the classroom list and its count, a batch read naming it fails as a whole with 404 (as a batch naming an unopened assessment does today), and 404 from opening it, autosaving or reading saved answers, submitting, and reading their submission. The check takes the student, not only the time, so no path can skip it.

**Students see that it is a resit.** A student's list entry and assessment carry `resit: true`. They never see the bank, other students' assignments, or which questions came from the bank.

**The original grade is never changed.** A resit is graded, reviewed, finalized and released like any assessment, and both grades stay in the student's results. Analytics needs no change. Its "Needs practice" flag reads a topic's latest ten questions in the order Analytics first received their grades, so a resit lifts the flag only once its grade arrives after the original's and its questions on the topic outweigh the earlier wrong ones. "Best of" and replacing grades are not part of this decision.

### Picking questions

**The teacher picks, with suggestions and no model call.** The bank list filters by topic, type, prompt text and origin. Given one of the teacher's classrooms and a student on its roster, it marks each bank question the student has already answered in any of that teacher's classrooms, including ones the student has since left (they submitted an assessment holding a question linked to it), and can hide them. Reaching past the current roster is deliberate: it is the teacher's own past assessment of a student they teach now, shown only as a hint and never as a grade or list, so ADR 0010's roster rule for teacher lists does not apply. Assessment owns the links and the submissions, so this is a local indexed query; the caller must teach that classroom and the student must be on its roster, so no teacher can probe another student's history. The resit builder suggests students and topics from the original's finalized grades in Grading, whose evidence carries each question's topic and marks; drafts are left out, since a question waiting to be marked shows no marks yet. The web app reads them with the teacher's token. Filling gaps with question generation and the adaptive resit agent (`docs/architecture/agentic-workflows.md`, workflow 4) are later work.

**Student self-practice is not part of this decision.** Ungraded practice that no teacher finalizes needs its own rules about grades and evidence, and gets its own ADR.

## Consequences

- No new service, topic or event version. `Question` and `assessment.submitted.v4` are unchanged, so Grading grades a resit as it is; link ids and the server-set fields travel in their own request and response types. The create and edit requests now refuse a top-level `id` or `published_at` (400), which they silently accepted before; the contract never listed either. Grading deduplicates by submission id, and its lists, counts, "Finalize all fully marked" and release only touch existing drafts of roster students, so unassigned students need no special case.
- Assessment migration `006_bank_and_resits.sql` is additive: `bank_questions`, `question_bank_links`, `assessments.assigned` (default false, so every existing assessment stays for the whole class), `assessments.resit_of`, `assessment_assignees`, and indexes on `submissions(student_id)` and `assessment_assignees(student_id)` for the student purge. A local setup needs `docker compose up -d --build assessment web`; Kong already routes everything under Assessment's prefix.
- Purges. `identity.user.deleted.v1` for a teacher deletes their bank questions (ADR 0011 already makes them delete their classrooms first, so the bank is the only teacher data left), and for a student deletes their assignee rows with the rest of their work. Bank writes take the teacher's user lock shared and check `deleted_users`, and changing assignees or creating a resit does the same for every requested student, so nothing lands after a purge. Creating a resit also takes the classroom's lock shared and checks `purged_classrooms`, as creating any assessment does. `identity.classroom.deleted.v1` removes the classroom's assessments with their links and assignees; the bank, which belongs to the teacher and holds no classroom material, stays. Unenrolment changes nothing in Assessment: an unenrolled student is off the roster and sees nothing, and sees their resit again if enrolled again.
- Teacher summaries and the classroom progress list gain `resit_of` and `assignee_count` (the number of assigned students on the roster, null for the whole class), and the detail gains `assignees`. The class dashboard counts submissions out of `assignee_count` when it is set. `submissions` still counts students on the roster who submitted.
- A question reused from the bank has no marking points, so AI marking suggestions for it rest on the rubric and model answer alone.
- ADR 0004's "not built yet" list keeps the second AI opinion and the agreement measurement; the question bank and resits move here. ADR 0006's expectation that the bank reuses `sources` is replaced by "The bank holds no passages" above; it keeps `origin`.
