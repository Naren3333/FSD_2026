# ADR 0015: Question generation critic loop

Status: accepted 2026-10-24. The project owner asked for the third agentic workflow (the list is in `docs/architecture/agentic-workflows.md`). It amends ADR 0006.

## Context

ADR 0006's pipeline drops drafts whose quote is not in the materials, whose key does not fit its options, or that repeat another question. It cannot tell whether a question is answerable from its passages alone, whether the key is the right one, or whether the wrong options are too obvious to be useful. A draft that passes the checks can still be a poor question, and a dropped draft was simply lost.

## Decision

**A second model pass reviews every draft that passed the checks, and rejected drafts are written again with the reviewer's reason.**

- The reviewer sees each draft's prompt, options and only its cited passages. It does not see the generator's key explanation or evidence, so it works out the answer for itself. It judges: answerable from the passages alone, key matches the answer it worked out, only one option can be right, wrong options plausible, and not a repeat of the assessment's existing questions.
- A draft that fails goes back to the generator with the reason, up to two retries (`QUESTION_REVIEW_RETRIES`), and the loop stops early when no type is short. A retry runs on any shortfall: rejected drafts, a short reply or an empty one. A request makes at most six model calls (three writes, three reviews), all billed to the teacher through ai-core (ADR 0003). The deadline (`QUESTION_REVIEW_DEADLINE`, default 240 seconds, clamped to 30–240) means a retry starts only if the time so far plus 1.5 times the longest round so far fits, leaving room for a slower round; when no retry fits the drafts so far are returned. Every call after the first generation is also cut off at the deadline, and one with under 5 seconds left is not started, so a slow round ends with the drafts it has (unreviewed if the review was cut off, `422 GENERATION_REJECTED` if there are none) instead of running past Kong's 300 seconds.
- Verdicts fail closed: an unreadable reviewer reply, a missing verdict for a draft, or an unknown reason never counts as a pass. A draft the reviewer gave no usable verdict on is not a failure either: it comes back `not_reviewed` with a note, counts towards its type's count (no retry is paid to replace it) and shows as `NOT_REVIEWED` in the round's reasons.
- Drafts flagged as weak are not "existing questions" on a retry: they reach the generator only as `previous_attempts` with their problem, so a corrected rewrite of the same stem is not dropped as a duplicate. When a rewrite passes it comes first and the weak draft is cut by the count. Flagged drafts are taken newest round first, and one whose prompt is at least 0.75 similar (`REWRITE_RATIO`, looser than the 0.9 duplicate check) to a draft already chosen is taken to be its older version and counted as dropped, so a weak draft and its rewrite are never returned together.
- A retry whose generate call fails still marks the previous round `retried`. A retry whose reply cannot be read adds a round with the reason `UNREADABLE_REPLY` (nothing written), and the drafts so far are returned. When nothing is kept and a retry stopped on an upstream error, the teacher gets that error (429, 502 or 503), and on an unreadable retry reply `502 AI_OUTPUT_REJECTED`, not `422 GENERATION_REJECTED`, which is kept for when every round ran and nothing passed.
- A draft whose only complaint is weak wrong options is kept and shown flagged, with the reviewer's note, so the teacher can fix the options rather than lose the question. Passed drafts come first.
- When the reviewer cannot run (a failed call, or the deadline), the drafts that passed the checks are returned marked `not_reviewed`, with a note saying why. Nothing is marked passed without a review.
- A teacher can skip the review per request (`review: false`) for a faster, cheaper run checked only against quotes. `QUESTION_REVIEW`, `QUESTION_REVIEW_RETRIES` and `QUESTION_REVIEW_DEADLINE` set the defaults on the service. `QUESTION_REVIEW` is off for `off`, `false`, `0` and `no` (any case, spaces ignored); anything else, or unset, is on.
- The response reports each round (written, passed the checks, passed the reviewer, rejected by reason, whether the review returned verdicts (`reviewed`) whether a later round ran (`retried`) and `sent_back`, the counts by reason of the round's drafts fed back to the generator) and the number of model calls. The new reason codes are `NOT_ANSWERABLE`, `WRONG_KEY`, `AMBIGUOUS`, `WEAK_DISTRACTORS`, `REPEATS_EXISTING` and `NOT_REVIEWED`.
- The reviewer also fails a draft as `NEEDS_MATERIALS` when a student who has not seen the passages could not understand it ("described", "in the examples", "according to the slides"). Such a draft is sent back and dropped, never flagged. A fixed list of phrases that only refer to the source ("according to the passage(s)", "according to the materials", "according to the text", "in the passage above", "in the text above", "the examples above", "the example above", "in the examples", "the described") is narrow on purpose, so "the passage of a law", "a slide" ("the slide before viewing cells", "how many slides"), "the materials" of materials science, and "described as" or "described in" (ordinary wording: "the powerhouse of the cell") pass. The slide phrases ("the slides", "on the slide", "in the slide") were removed from the list because they match ordinary questions; the reviewer covers them and the other wording the list leaves out. The list is checked before the reviewer, so it costs no model call. "the text" and "the material" are not on the list: they match ordinary questions ("the text-align property", "the material's tensile strength"), so the reviewer's `NEEDS_MATERIALS` covers them.
- `WEAK_DISTRACTORS` also covers a key noticeably longer than the other options, a wrong option ruled out by "only", "always" or "never", and a stem that repeats the key's defining words. A deterministic check treats a key of at least 40 characters and more than 1.8 times the average of the other options as the reason `LONG_KEY` (set by our code, not offered to the reviewer), but only after the reviewer has passed the draft (a draft the reviewer fails keeps the reviewer's reason): sent back, then kept flagged ("The answer is much longer than the other options.") after the last round, and flagged rather than dropped when the review is off. A flagged note carries `source`: `reviewer` (shown as "Reviewer: …") or `check` (our own check, shown as "Check: …", so a skipped review never shows a reviewer label). `REPEATS_EXISTING` also covers the same fact asked in another type or form.
- The reviewer is shown the editor's questions plus every draft held so far, including those that came back `not_reviewed`, and is told that when two questions in a batch repeat each other it fails only the later one, so one of a repeated pair survives.
- Counts are per question type, and a retry asks only for the shortfall of each type still short; the response lists the drafts grouped by type, passed ones first within each.
- The round summary reads `sent_back` rather than guessing: drafts fed back read "sent back to improve because…", the others "left out because…" (a `DUPLICATE` or `WRONG_TYPE` draft is never fed back), and weak or long-key drafts in the last round read "flagged because…". Whether a flagged draft is finally shown is visible on each card.
- Kong's read timeout for the agent and the web client's timeout are five minutes.

**The page** shows each draft's review status (passed, the reviewer's note when flagged, or why it was not reviewed), a "Skip the review" checkbox, and a "How the drafts were checked" disclosure with one line per round and the call count. Nothing is added to an assessment until the teacher adds it.

## Consequences

- After rebuilding, run `docker compose restart kong` so Kong picks up the longer timeout.
- A request now costs up to six model calls instead of one, and takes longer; the daily allowance applies to each call. The page says so while it loads and offers the skip.
- Real-key comparison on 2026-10-24 (5 multiple choice and 3 short answer, Intermediate, software-testing slides): both runs returned 8 of 8; the review made 2 calls against 1, each cost under $0.01, and the review run was slightly slower. The reviewer rejected nothing. Problems it missed: questions that lean on the materials ("in the described three-stage structure"), giveaway options (longest key, absurd or absolute-word distractors, stem restating the answer), and the same fact asked as short answer and multiple choice. The reasons and checks above came from that run.
- The reviewer checks drafts against the passages, not against the subject, so a mistake in the materials passes (a stub described as a "simulated caller", which is really a driver). The page's caption says so.
- Second real-key run after the tuning on 2026-10-24 (same slides, Advanced; 4 multiple choice, 2 short answer, 2 written response, review on): 8 of 8 returned in one round, 2 model calls (one write, one review), about 19 seconds, nothing sent back or dropped by the checks or the reviewer. Cost: not recorded. Still seen: "described as optimized for Vite" (the phrase list has "as described" but not "described as"), a stub called a "simulated caller" (the source error, unchanged by design), and weak distractors ("Run field trials to gather user feedback"). Not seen: a key past the length rule, or the same fact across types.
- Not built: reviewing marking guidance, a cheaper model for the reviewer, and extra searching for passages when a draft is sent back.
